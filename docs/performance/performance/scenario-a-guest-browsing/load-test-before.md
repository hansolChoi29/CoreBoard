# Load Test 개선 전

## 1. 테스트 목적

Scenario A - 비로그인 사용자의 게시판 탐색 흐름에서 대량 게시글 데이터 조건에서 주요 조회 API의 응답 시간, p95, 오류율, 처리량 변화를 확인한다.

이번 테스트는 약 142만 건의 게시글 데이터가 존재하는 상태에서 수행한다.

특히 게시글 목록 조회는 Page 기반 조회이므로 전체 개수 계산을 위한 count query와 최신순 정렬 비용이 발생할 수 있다. 따라서 게시글 목록 조회가 대량 데이터 조건에서 병목으로 나타나는지 확인한다.

## 9. 결과 해석

Scenario A Load Test는 5 users 단계에서 중단 기준에 도달했다.

게시판 목록 조회, 게시글 상세 조회, 댓글 목록 조회는 모두 비교적 안정적으로 응답했다. 그러나 게시글 목록 조회 page 0은 평균 14164ms, p95 18335ms, 최대 22044ms로 측정되었고,
page 1은 평균 15210ms, p95 20080ms, 최대 20296ms로 측정되었다.

따라서 Scenario A의 병목은 전체 API가 아니라 게시글 목록 조회 API에 집중되어 있다고 판단한다.

오류율은 0.0%였고 5xx 오류는 발생하지 않았다. 또한 Grafana 기준 DB 연결 대기 요청은 발생하지 않았다. 따라서 이번 지연은 DB Connection 부족보다는 게시글 목록 조회 쿼리의 count
query, 최신순 정렬 비용, Page 기반 조회 비용, 인덱스 부재 가능성을 우선 의심한다.

중단 기준에 도달했으므로 10 users, 20 users, 30 users 단계는 실행하지 않고 Bottleneck Analysis로 전환한다.

---

## 10. 결론

Scenario A - 비로그인 사용자의 게시판 탐색 흐름은 약 142만 건의 게시글 데이터 조건에서 5 users 단계부터 성능 병목이 확인되었다.

병목은 게시판 목록 조회, 게시글 상세 조회, 댓글 목록 조회가 아니라 게시글 목록 조회 page 0/page 1에서 발생했다.

게시글 목록 조회 API의 p95 응답 시간이 18초 이상으로 측정되어 중단 기준을 초과했기 때문에, 추가 부하 단계인 10 users, 20 users, 30 users는 실행하지 않았다.

다음 단계에서는 게시글 목록 조회 쿼리에 대해 Bottleneck Analysis를 수행한다. 주요 확인 대상은 count query, 최신순 정렬 비용, Page 기반 조회 비용, 그리고
`(board_id, status, created_at)` 복합 인덱스 적용 가능성이다.
