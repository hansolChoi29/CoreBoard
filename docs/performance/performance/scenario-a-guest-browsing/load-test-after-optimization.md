# Load Test - Scenario A 개선 후 재측정

## 1. 테스트 목적

Scenario A - 비로그인 사용자의 게시판 탐색 흐름에서 게시글 목록 조회 개선 후 API 응답 시간이 실제로 개선되었는지 확인한다.

개선 전 테스트에서는 약 142만 건의 게시글 데이터 조건에서 5 users 단계부터 게시글 목록 조회 API의 p95가 18초 이상으로 증가했다.

병목 분석 결과, 주요 원인은 게시글 목록 조회에서 `post JOIN users` 상태로 최신순 정렬이 수행되는 구조였다.

이번 테스트는 목록 조회에서 `join fetch p.user`를 제거하고, post 목록을 먼저 조회한 뒤 필요한 user 정보를 별도로 조회하도록 개선한 뒤 수행한다.

## 9. 결과 해석

개선 후 5 users 재측정 결과, 전체 p95는 354ms로 측정되었다.

개선 전 5 users 테스트에서는 전체 p95가 18322ms였으나, 개선 후에는 354ms로 감소했다.

특히 병목이 발생했던 게시글 목록 조회 API의 응답 시간이 크게 개선되었다.

- page 0 p95: 18335ms → 384ms
- page 1 p95: 20080ms → 363ms

게시판 목록 조회, 게시글 상세 조회, 댓글 목록 조회는 개선 전과 동일하게 안정적인 범위에서 응답했다.

오류율은 0.0%였고, 5xx 오류는 발생하지 않았다.

Grafana 기준 CPU, JVM Memory, DB Connection에서도 서버 전체 자원 부족으로 볼 만한 이상 징후는 확인되지 않았다.

따라서 게시글 목록 조회에서 `post JOIN users`를 제거한 개선이 유효했다고 판단한다.

---

## 10. 결론

Scenario A 개선 후 5 users 재측정에서 게시글 목록 조회 병목은 크게 완화되었다.

개선 전에는 5 users 단계에서 p95가 18초 이상으로 증가하여 중단 기준에 도달했다.

개선 후에는 전체 p95가 354ms로 측정되었고, 게시글 목록 조회 page 0/page 1도 p95 0.4초 이하로 응답했다.

이를 통해 기존 병목의 주요 원인이 게시글 목록 조회에서 `post JOIN users` 상태로 최신순 정렬을 수행하던 구조였음을 확인했다.

다음 단계에서는 동일한 개선 상태에서 10 users, 20 users, 30 users를 순차적으로 실행하여 부하 증가 시에도 안정적인지 확인한다.
